# Workflow regression tests

`make check` runs each spectroscopy workflow (IR, Raman, SFG with Fresnel
factors, and power) on small inputs and compares every stage's output with
reference outputs from the pinned pre-modernization `master` commit recorded
in [reference/PROVENANCE](reference/PROVENANCE). These tests guard against
changes to the build system or dependencies altering results. The
[trajectory regression suites](../src/unittests/README.md) cover additional
numerical, analytical, and input-handling cases.

| Test | Stages | Models exercised |
|------|--------|------------------|
| `ir.test` | dipole → response → spectrum | MB-μ 1B + 2B (LTP2011, poly2b5) |
| `raman.test` | polarizability → response → spectrum, depolarized and isotropic | MB-α 1B + 2B + NB (Avila, poly2b3, TTM4, periodic TTM4) |
| `sfg.test` | response → spectrum for zzz, xxz and xzx, then fresnel | 1B + 2B dipoles and polarizabilities, auto + cross correlation |
| `power.test` | response → spectrum | velocity autocorrelation |

## Files

- `data/`: the inputs. `water4.xyz` holds 4 flexible waters over 8 frames, one
  pair inside the 2B switching region. `water4-sfg.lammpstrj` holds two slabs
  with dipole columns, and `water4-vel.lammpstrj` holds velocities. There is one
  JSON file per workflow. The inputs are generated by `data/generate-inputs.py`
  (not run by `make check`) and use LF line endings, which the readers require.
- `reference/` contains the saved outputs. `reference/PROVENANCE` records the
  commit, compiler, flags and MKL version used to produce them.
- `compare.sh`: compares a file with its reference, field by field. Numeric
  fields may differ by `1e-8` relative, `1e-10` of the column's largest
  magnitude, or one unit in the last printed digit. Text fields and the
  file's shape (lines and fields per line) must match exactly. The script
  reports the largest deviation for each file.
- `common.sh`: helpers shared by the `*.test` scripts. The tests run with
  `OMP_NUM_THREADS=1`, because the SFG and power responses sum across threads
  in arrival order.

After building the programs, run `make -C tests check` from the top-level
build directory to run these tests on their own. Set `MBSPEC_KEEP_WORK=1`
to keep a test's temporary work directory.

## Regenerating the references

The references must come from the pre-modernization `master` commit recorded
in `reference/PROVENANCE` (`c516736`), not from this build. With Intel MKL
initialized (`MKLROOT` set) and Clang, GSL and Autotools installed:

```bash
git worktree add --detach /tmp/mbspec-master c516736c3946166e0ee81b2198854a67da660c99
sh tests/generate-reference.sh /tmp/mbspec-master tests/reference
```

The script builds master with its own build files and no source changes.
Master's root `Makefile.am` lists a missing `autogen.sh`, so the script builds
`src/` only. It passes `-fopenmp`, as master's `compile.sh` did, and uses
`clang++` by default.

Under GCC's C++11 mode, which master selects for `src/tools`, master numbers
LAMMPS dump columns from 1 instead of 0 and reads the wrong columns, because
of unsequenced evaluation in `read-lammpstrj.cpp`. Clang, and master's
documented compiler `icpx`, number them correctly. This branch builds as
C++17, where the order is well defined for every compiler.

CI repeats this generation and compares the result with the committed
references, which confirms that they really come from master.
